REVIEW 1

Problem Statement

  • Traditional hall booking is often managed manually through registers, calls, or messages.
  • This can cause double bookings, scheduling conflicts, and difficulty in tracking availability.
  • Users may not get real-time information about available halls and time slots.
  • A computerized online system is needed to make hall booking faster, easier, and more reliable.
  • The project demonstrates the application of OOP concepts to a real-world booking problem.
03
REVIEW 1

Objectives

  • Develop a simple Online Hall Booking System using OOP.
  • Allow users to view available halls and time slots.
  • Enable users to book, update, and cancel hall reservations.
  • Avoid duplicate bookings and scheduling conflicts.
  • Provide administrators with tools to manage halls and bookings.
  • Demonstrate Classes & Objects, Encapsulation, Inheritance, Polymorphism, and Abstraction.
04
REVIEW 1

Scope of the Project

  • User registration and login.
  • View hall details, capacity, facilities, and availability.
  • Search halls by date, time, capacity, or type.
  • Create, update, and cancel bookings.
  • Admin management of halls, users, and reservations.
  • Generate basic booking and availability reports.
  • Suitable for college/class-level halls and small institutions.

REVIEW 1

Modules of the Project

  • 1. User Module – Register, login, and manage user details.
  • 2. Hall Module – Add, view, update, and delete hall information.
  • 3. Availability Module – Check halls and available time slots.
  • 4. Booking Module – Create, update, and cancel reservations.
  • 5. Admin Module – Manage users, halls, and bookings.
  • 6. Report Module – Display booking and availability summaries.
07
REVIEW 1

OOP Concepts Used

  • Class – User, Hall, Booking, HallManager, etc.
  • Object – Individual users, halls, and booking objects.
  • Encapsulation – Keep data private and access it through methods.
  • Inheritance – Specialized user or hall classes can inherit common properties.
  • Polymorphism – The same method can behave differently for different objects.
  • Abstraction – Hide unnecessary implementation details from users.
